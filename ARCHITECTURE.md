# Architecture

## System Overview

AI Public Speaking Coach uses a split frontend/backend architecture.

```text
User Browser
  -> Next.js Frontend
  -> FastAPI Backend
  -> Gemini API
  -> Supabase PostgreSQL
```

## Frontend

Location: `frontend/`

Technology:
- Next.js App Router.
- TypeScript.
- Tailwind CSS.

Responsibilities:
- User interface.
- Authentication screens and client-side auth state.
- Dashboard and practice experience (e.g., topic configuration and generation).
- Browser audio recording.
- Calls to the FastAPI backend.

The frontend does not call Gemini directly. AI keys must remain server-side.

## Backend

Location: `backend/`

Technology:
- FastAPI.
- Python.
- Pydantic.
- Uvicorn.

Responsibilities:
- API routing and request validation.
- Authentication verification (validates Supabase bearer JWTs).
- Database interface (Supabase PostgreSQL client).
- Gemini API integration (prompts generation and response schema structure validation).

The backend owns privileged secrets such as the Supabase service role key and Gemini API key.

## Database

Provider: Supabase PostgreSQL.

### Table Schema: `topics`
Records speaking prompts generated by users for their practice sessions.
```sql
CREATE TABLE public.topics (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    category TEXT NOT NULL,
    difficulty TEXT NOT NULL,
    title TEXT NOT NULL,
    prompt TEXT NOT NULL,
    context TEXT NOT NULL,
    suggested_points JSONB NOT NULL DEFAULT '[]'::jsonb,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);
```

#### Row Level Security (RLS)
The `topics` table has RLS enabled with the following security policies:
- **SELECT Policy**: `auth.uid() = user_id` ensures users can only read their own topic history logs.
- **INSERT Policy**: `auth.uid() = user_id` ensures users can only save topics under their own authenticated user ID.

### Table Schema: `speeches`
- Planned table for session audio recordings, transcriptions, and coach feedback records (deferred for the next milestone).

## Authentication

Provider: Supabase Auth.

Flow:
1. User registers or logs in through the frontend.
2. Frontend receives a Supabase session JWT.
3. Frontend sends requests to the backend with header: `Authorization: Bearer <JWT>`.
4. Backend's `get_current_user` dependency calls `supabase.auth.get_user(jwt)` to verify the session before permitting access to protected resources.

## AI Analysis & Topic Generation

Provider: Gemini API (`gemini-1.5-flash`).

Flow:
1. User requests a topic from the dashboard.
2. FastAPI backend handles the request, authenticates the user, and calls the Gemini SDK.
3. Gemini is configured with `response_mime_type="application/json"` and `response_schema` mapped to Pydantic objects (`TopicListResponse`) to guarantee a structured response.
4. Backend saves the generated topic under the user's ID in the `topics` database table.
5. Backend returns the topic list container to the client for rendering.

## Security Principles
- Do not expose Gemini API keys or Supabase service role keys to the browser.
- Validate backend inputs/outputs with Pydantic schemas.
- Use environment variables for secrets.
- Enforce strict Row Level Security (RLS) policies on all tables.
- Restrict CORS origins.

## Deployment Targets
- Frontend: Vercel.
- Backend: Railway.
- Database and Auth: Supabase.
